# 编码类任务派单红线模板（复制后填空）

> 适用：把产品代码实现/修复分包给 TeleAgent 工程师。每条都是真实事故换来的，
> 复制本模板后只填空，勿删红线段落。`<...>` 为必填占位符。

## 任务信息

- 任务编号/标题：`<TASK-ID 标题>`
- 唯一工作 worktree：`<绝对路径>`（分支 `<branch>`，基线 commit `<SHA>`）
- 开工条件：`git status` 必须干净且 HEAD 等于基线 SHA；不符立即 STOP 上报，
  不要自行 stash/reset/checkout 任何东西。
- git 可执行文件：`<git 绝对路径>`（机器无全局 git 时必填，命令一律用
  `"<git路径>" -C <worktree> ...`）

## 1. 角色与开工阅读序

按顺序只读以下材料，前者优先级高于后者；本任务书高于一切默认判断：

1. `<需求/契约文档绝对路径>`（最高优先级）
2. `<相关现状代码文件绝对路径列表>`
3. `<测试规范/验收标准绝对路径>`

## 2. 唯一工作对象与文件域

- 可修改的产品文件**仅限**：`<file-a>、<file-b>、<file-c>`。
- `git status` 出现任何域外 M/A/D 文件 → 立即 STOP，不要替别人收拾。
- 明确声明不得改写的区域：`<如 server / 配置白名单 / 桥接层 / 公共协议>`。
- 不新建任务书之外的目录；临时件只写第 4 节证据目录，自建自销。

## 3. 实现清单（逐条锚点，禁止自由发挥）

1. `<契约第 N 行锚点>`：要实现的语义与冻结点（哪些既有行为字节级不变、
   旧数据如何兼容、键/字段集合不增不减）。
2. `<...>`

## 4. 三凭证（全部绝对路径）

- 解释器/虚拟环境：`<python 或 node 绝对路径>`。
- 回归 runner 与必传参数：`<runner 绝对路径> <参数>`；说明必过的
  既有套件与受影响范围套件的脚本路径。
- 证据目录：`<绝对路径>`，其下建 `logs/`、`tmp/`、`harvest/` 子目录；
  所有 TR 日志、复跑产物只写这里。

## 5. 测试要求

- 每条验收点 TR 独立可跑、离线可重复（桩/故障注入/本地伪服务），
  **禁止真实联网与真实账号**。
- 日志尾部写断言计数，固定格式：`TRx 结论：PASS（N 项）`。
- 必跑：`<最小冒烟脚本路径>` 与受影响的历史回归套件；全部列出脚本路径，
  不许写"相关测试已通过"这种无证据结论。

## 5A. 测试 seam 先行（含逻辑的任务必留；纯样式/纯文案任务整节删除，
##     并在派单说明注明"本任务无逻辑，5A 已删"）

- 开工第一件事：把每个验收点的测试 seam（公共边界：路由/导出函数/事件/
  CLI/DOM 可观察行为）逐条写入 `<证据目录>/seams.md`，每条写明经哪个
  公共入口驱动、断言什么可观察行为、能抓住什么/漏掉什么。
- 先写一条测试并**亲自跑过一次看到红**，再做最小实现转绿，纵切推进；
- 测试经公共接口验行为，不断言私有结构/调用顺序；禁实现耦合、同义反复、
  水平切片（纪律全文：`<项目纪律目录>/tdd-seams.md`，开工时只读遵守）。

## 5B. 缺陷诊断阶段门（缺陷修复/热修类任务必留；功能新增任务整节删除，
##     并在派单说明注明"本任务非热修，5B 已删"）

- 提出根因假设、修改产品代码**之前**，必须先造出针对本 bug 变红的紧反馈
  回路（失败测试/伪服务故障注入/headless 复现/fixture），写入
  `<证据目录>/repro/`，并已亲自跑过一次看到红、连跑 3 次稳定复现。
- 造不出红回路立即 STOP 上报已试回路与缺失条件，禁止"先改了试试"；
- 修复后红回路变绿且回归测试留在正式测试目录；插桩自建自销，契约/冻结点
  本身有误不顺手改，STOP 报派单方
  （纪律全文：`<项目纪律目录>/diagnosing-bugs.md`）。

## 6. 红线（原文照抄，不可协商）

- 严禁 `commit / push / merge / rebase / tag / git add -A`；commit 由
  收割工程师在隔离环境独立复跑后做，你只负责把工作树改对。
- 禁真实账号、真实联网、真实付费/写操作；不引新依赖、不加 CDN、
  不加网络白名单/新出站方法（契约明确批准的既有方法参数扩展除外）。
- 禁碰任何产物/数据目录下的真实用户数据（只读参考结构可以）。
- 授权只申请本次操作的最精确叶子目录，绝不申请盘符/用户主目录等祖先目录；
  shell 优先把 cwd 设为系统临时目录或 TeleAgent 数据目录，命令内全用绝对路径。

## 7. 收口格式（完成后立即结束，等收割，不要顺手优化别的）

把结果写入 `<证据目录>/<TASK-ID>_<包名>_result.md`，含：

- 改动 numstat（`git diff --numstat` 原文）；
- TR 断言计数与每条日志的绝对路径；回归结论（脚本+命令+结果原文片段）；
- 给下游的形状备忘（接口/数据形状变化，无则写"无"）；
- 偏差清单：与任务书不一致处诚实记录，没有写"无"；
- 完成标记：最后一行固定写 `<TASK_ID>_DONE`。

## 派单方派单后立刻做（顺序）

1. 从 dispatched 事件 JSON 记 `session_id`，登记不可丢。
2. 用带看守的 `run`（默认即一体化）；不要裸 dispatch 后无人看。
3. 授权根参数：`--workspace <worktree>`（必要时再加 `--source <主检出>`
   与 `--allow <worktree> <证据目录>`）。
4. 末行非 done 必为 fallback_needed：按其 recommended_actions 处置，
   不重派仍在推进的会话，不找用户点界面。

## 收割工程师任务书要点（独立会话，不信任执行者自报）

- `git status/diff --numstat` 通读，核对文件域；冻结点对基线做
  blob/字节级比对；协议/白名单类改动逐项手工点数。
- TR 脚本**复制到证据目录 harvest/ 下隔离独立复跑**，日志不得覆盖
  原工程师日志；数据分歧用可复现实验裁决，拿不准 STOP 上报。
- 全绿后仅 `git add` 文件域内文件并 commit（记 SHA/parent/numstat）；
  **禁 push/merge/tag**；回报 commit SHA 与一句话结论。

## 评审会话要点（双轴；仅契约冻结/发版门等评审波启用，两个独立会话并行）

- 一会话只审 **Standards**（编码约定+确凿坏味道，依据
  `<项目纪律目录>/code-review-two-axis.md` 与任务书所列项目约定），
  另一会话只审 **Spec**（逐条对原始任务书/冻结契约+固定点 SHA）；
  两轴互相隔离，不参考对方报告，不合并排名。
- 评审范围 = `git diff --numstat <固定点SHA>...HEAD`；域外改动直接记 hard。
- 只读评审：不修改产品文件、不 commit，只写本会话自己证据目录下的报告；
  每条 finding 引文件+原文行，hard 与 judgement 分列；末尾固定
  `评审结论：PASS` 或 `评审结论：FAIL（hard N 项）`，无 finding 也要出报告。
- 任一轴 FAIL 不合线：派单方另派修复会话，评审会话不得自行修复
  （修了即丧失独立性）。

## 会话 abort/停滞接续范式

1. `messages --session <id> --last 8` 看断点；`git status`/`git diff --numstat`
   核现场是否完好。
2. 现场完整（代码在、日志在、产物在）→ `resume --session <id>` 派接续
   会话（工具会自动生成"严禁重做已完成部分、只做剩余收口"的接续任务书）。
3. 模型/供应商错误（finish=error、provider not found、限流）→
   `resume --next-model` 换凭据就绪供应商续派。
4. 现场损坏 → 评估丢失工作量后重新 run，新任务书附断点证据。
